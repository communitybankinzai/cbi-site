1. 何を計算し、何を計算していないか

内容
計算しているもの地形だけから求めた「雨水がたまりやすい傾向」の相対指標（0〜100の無次元量）。および、一様・一定の雨を仮定したときの、その指標の縮小表示。
計算していないもの浸水深（m）、冠水確率、通行可否、湛水の継続時間、氾濫の時間変化、外水（河川）氾濫、下水道・側溝・ポンプによる排水、先行降雨による土壌の湿り、解析範囲外からの流入。
校正の状態未校正。重み・しきい値はいずれも仮設定で、実際の冠水実績との照合を行っていません。したがって見逃し率・誤警報率は不明です。

3. 地形指標の算出（topo-0.2.0）

3.1 格子

標高タイルの画素を、各セルに入るぶんだけ平均して集約します。格子は 283列 × 266行、範囲は南西 (35.717910, 140.067782)、北東 (35.911679, 140.322005) の矩形です。 行政界ではないため、白井市・栄町・成田市など隣接自治体を含みます。有効セルは75,278（欠測なし）。 格子は Web メルカトル（EPSG:3857）で 1セル＝メルカトル上の100 m。地上では約81 mにあたるため、 面積・距離・傾斜は行ごとの縮尺係数 cos(φ) を掛けて地上値に直して計算しています。

3.2 窪地処理と流向・流量

  • 窪地埋め：Priority-Flood。埋める前後の標高差を「窪地深さ（depression_depth, m）」として保持します。単純に埋めると窪地の跡が完全に平坦になり D8 が下流を選べなくなるため、流下計算には内側へ進むごとに 1×10⁻⁵ m を足した ε 版の標高を使います（Barnes ほか）。窪地深さは ε を足さない方から求めます。
  • 流向：D8（8方向の最急勾配1方向へ流す）。
  • 流量：上流から流れ込むセルの地上面積の積算（flow_accumulation_m2, m²）。1セルは約6,560〜6,592 m²。
  • 相対標高（relative_elevation, m）：半径3セル（地上 約240 m）の円形近傍の平均との差。負が「周りより低い」。
  • 傾斜（slope, 度）：Horn 法（3×3）。地上セル寸法で除算します。

3.3 合成式（本ページ公開時にデータから逆算・検証した）

この合成式は、前の版（topo-0.1.0）の公開データから逆算して確定させたものです。生成スクリプトが外部環境にあり回収できなかったため、出力から式を復元しました。

score = 100 × [ 0.25 · clip( −相対標高 / 5 m )
            + 0.35 · clip( 窪地深さ / 2 m )
            + 0.25 · clip( log₁₀( max(1, 集水面積) ) / log₁₀(10⁶) )
            + 0.15 · clip( 1 − 傾斜 / 10° ) ]

clip(x) = min(1, max(0, x))
検証：前の版の有効セル74,110すべてで上式と保存値を突き合わせ、最大誤差 0.12 点（保存値の丸めの範囲）、誤差0.5点を超えるセルは0件でした。現在の版はこの式をそのまま実装しています（build_static.py）。 重み（0.25／0.35／0.25／0.15）と正規化スケール（5 m／2 m／10⁶ m²／10°）は status.json の記載と一致します。

※ 重みとスケールの根拠：ありません。文献値でも実績からの推定値でもなく、開発時に置いた仮の値です（status.json も calibration_status: 仮設定・未校正 と記録しています）。

4. 道路への割り当て

  • 対象：OSM の highway が motorway／trunk／primary／secondary／tertiary（および各 _link）／unclassified／residential／living_street の18,024本。歩道・階段・農道・敷地内通路（footway, path, steps, cycleway, track, service 等）は除外。
  • 各ノードの座標が入る格子セルの score から区分を決め、区分が変わる位置で線を分割して24,603本の線分にしています（切れ目の点は両側に含め、隙間を作りません）。
  • 格子の行の引き当てには、緯度をそのまま比例配分せずメルカトルY座標に変換してから引いています（比例配分では最大で数十mずれるため）。
  • 配信データは座標を1×10⁻⁵度（約1.1 m）に量子化し、線ごとの差分で保持（road_risk.json・1.18 MB）。

この割り当ては「その道が通っている地形の傾向」であって、道路構造の評価ではありません。路面高、縁石、アンダーパス、橋・高架（橋の上と下の道を区別していません）、side walk の有無はいずれも未考慮です。

5. 雨量シナリオ（cbi-rain-sensitivity-0.2.0）

防災MAPの「CBI独自シミュレーション」で、雨量 R（mm/h）と継続時間 T（時間）を入力したときの計算です。

E = max( 0, R × C − D ) × T
参考指標 = score × E / ( E + 50 )
記号意味既定値備考
C流出率0.8市内の実測値ではありません。全域一律。
D排水相当量（mm/h）0全域一律の定数です。場所ごとの排水能力の差を表せません。
50感度の尺度（mm）—表示の効き方を決める任意の仮尺度で、冠水が始まる基準ではありません。

この式の重要な性質（誤解されやすい点）

E / (E + 50) は地図全体に共通のスカラーです。したがって雨量や継続時間を変えても、 全セルが同じ倍率で薄く／濃くなるだけで、地点どうしの危険度の順位は一切変わりません。 「50 mm/h なら A地区が、100 mm/h なら B地区が危ない」といった、雨の強さによる危険箇所の入れ替わりは表現できません。

また E は単純な水収支であって湛水深ではなく、同じ E であれば降り方（ピークの時刻・降雨波形）が違っても同じ結果になります。 入力を 0 にしても、残留水や外水氾濫を考慮しないため「安全」を意味しません。

6. 既知の不正確さ

6.1 座標系の不整合は修正しました（topo-0.2.0）

前の版（topo-0.1.0）は status.json に processing_crs: "EPSG:32654"（UTM 54N）・cell_size_m: 100 と記録しながら、 実際には Web メルカトル（EPSG:3857）の100 mをそのまま地上100 mとして扱っていました。北緯35.8度では地上約81.1 mにあたるため、 集水面積が約1.52倍に過大、傾斜が約19%過小になっていました（実際、旧データの集水面積の最小値は1セル＝10,000 m²でした）。

現在の版では、格子は Web メルカトルのまま（表示の重ね位置を変えないため）で、 面積・距離・傾斜の計算時に行ごとの縮尺係数 cos(φ) を掛けて地上値に直しています。 1セルの地上面積は6,560〜6,592 m²です。UTM へ移さなかったのは、この地域では子午線収差により最大約100 mの回転ずれが生じ、 地図への重ね合わせが崩れるためです。

あわせて、窪地を埋めた後の平坦部で D8 の流れが止まる不具合も見つかり、ε 版で修正しました （修正前は集水面積の平均が本来の47分の1になっていました）。

6.2 その他の限界

  • 排水が場所によらない：管路・側溝・ポンプ・調整池は未実装。D は全域一律の定数です（第7節）。
  • 解析範囲外からの流入を考慮しない：矩形の縁で流域が切れています。
  • 河川氾濫（外水）を含まない：利根川・印旛沼水系の氾濫は別の現象です。
  • 先行降雨・土壌の湿りを考慮しない：流出率は固定です。
  • 橋の上と下を区別しない：DEMは橋面を拾うことがあり、アンダーパスの路面高は表せません。
  • 公式の内水ハザードとは別物：市の公式想定は特定の降雨条件（2008-08-30 我孫子観測所 最大1時間105 mm）に対する想定図であり、現況の正解データではありません。当方はその区域データを取得できていないため、照合も行っていません。
  • 前の版の定義を完全には復元できていない：相対標高の近傍の取り方と傾斜の求め方は、旧データから逆算しても一致しませんでした（最良の当てはめでも平均誤差0.38 m／0.32度が残る）。現在の版は本実装で定義を決め直し、明記したものです（半径3セルの円形近傍・Horn 法）。旧版と数値が完全に一致することはありません。

7. 排水能力を反映するために必要なデータ

「排水能力は場所によって異なる」というご指摘のとおりで、現行モデルの最大の欠落はここです。 費用対効果の高い順に3段階で整理します。

8. 再現と照会

  • 格子データ：map_grid.json（283×266、score／elevation／slope／depression_depth／flow_accumulation_m2／relative_elevation）
  • パラメータと生成日時：status.json（※ 6.1 の食い違いに注意）
  • 標高データの取得元・チェックサム：sources.json
  • 道路の色分けデータ：road_risk.json
  • 雨量シナリオの実装：cbi-simulation-core.js（計算部・約20行）
  • 地図の実装：naisui.html
  • 生成スクリプト：pipeline/build_static.py（標高タイル取得→格子化→Priority-Flood→D8→指標→合成）、pipeline/build_roads.py（道路への割り当て）、pipeline/fetch_roads.py（OSM取得）

生成スクリプトを公開しているので、python pipeline/build_static.py で第三者が同じ格子を作り直せます。標高タイルはキャッシュされ、2回目以降は地理院サーバーへ取りに行きません。
